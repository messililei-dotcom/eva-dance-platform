## Xcode 设置与实际结果

- Xcode 27.0（27A266a），开发目录 `/Applications/Xcode.app/Contents/Developer`；`xcodebuild -checkFirstLaunchStatus` 返回 0。
- 已下载并安装 iOS 27.0（24A434，arm64）模拟器运行环境。
- 工程已在 Xcode 打开；选择 EvaDance-Fixtures Scheme、iPhone 18 Pro Max 模拟器。该 Scheme 的 Debug 运行使用 loopback 样本接口；EvaDance 正常 Scheme 和所有 Release 构建仍使用正式 App API 地址。
- iOS Simulator 通用 Debug 构建通过。随后发现具体模拟器目标构建时 App 默认同时构建 x86_64，而本地 Swift Package 仅提供当前 arm64 模块，导致 EvaCore 不兼容。已在生成脚本及工程设置 Debug `ONLY_ACTIVE_ARCH=YES`；针对 iPhone 18 Pro Max 的完整构建复验通过。
- iPhoneOS Release 未签名构建通过。它不是可安装分发 IPA，也不是签名 Archive。
- 已在 iPhone 18 Pro、iPad Pro 11-inch (M5) 模拟器安装并启动 App；启动后再次核对进程仍在运行，launchctl 状态为 0。
- Device Hub 启动后，自动化界面读取持续 timeoutReached。已尝试从 Xcode 入口打开、重启设备中心，仍无法读取其 UI。因此本轮不能把 iPhone/iPad 点击、横屏、字号和视觉验收记为通过。Xcode 的最后一次按钮运行曾显示架构错误；该错误修复后的成功证据来自同 Scheme、具体模拟器目标的 xcodebuild，尚未再次确认 GUI Run 完成。

## 服务端变更和部署前步骤

新增 `/api/app/v1/[...path]`、app-session、app-route-map 及 middleware 入口。App 手机登录使用 ios_app 来源，15 分钟访问令牌与 30 天刷新令牌；旧小程序身份令牌只在服务器内部适配既有业务 handler。App API 不开放任意后台路由，资料响应过滤微信身份与管理备注，订单创建和支付被阻断。

`ensureAppSchema` 以 CREATE IF NOT EXISTS 新增 AppSession、AppSpentRefresh、AppLoginAttempt、AppDeletionRequest、AppLearningCheckpoint 及 pending 注销唯一索引；不删除现有业务表。生产上线前应先备份实际 admin.db，在副本核对迁移、索引、会员归并、真实短信流程与全部业务响应，再做可回滚部署和正式域名联调。当前未执行生产迁移。

App 续播点允许后退并使用 revision 拒绝过期写入；旧小程序 MAX 完成度逻辑仍保留，不能声称跨端精确续播已经统一。注销申请仍是 pending，实际数据删除、保留处理与其他端会话撤销未完成。

## 复现本地调试

1. 打开 `../EvaDance/EvaDance.xcodeproj`。
2. 使用 Python 3 运行 `../EvaDance/scripts/fixture_server.py`，它只监听 127.0.0.1:18765，不连接生产。
3. Xcode 选择 **EvaDance-Fixtures** 和已安装的 iPhone/iPad 模拟器，点击 Run。示例手机号 13800000000、验证码 123456 仅用于本地样本，真实服务器无此测试后门。
4. 正式环境使用 EvaDance Scheme。新 API 尚未部署前，正式地址返回失败是预期阻断，不要回退到小程序身份令牌。
5. 工程由 `scripts/generate_project.py` 生成；设置改动同步脚本，保留可复现性。真实 Team 和签名在组织账号准备好后配置。
