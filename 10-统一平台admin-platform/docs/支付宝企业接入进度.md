# 支付宝企业接入进度

## 当前状态

目标主体为伊娃文化艺术发展（湖南）有限公司。此前个人商户应用及个体工商户申请不能作为企业认证或企业网站支付权限的证明，也不自动迁移到公司。

上次已看到企业注册草稿，并到达法人电子营业执照扫码授权步骤。本轮读取该申请被重定向至支付宝登录页，因此企业授权、开户、审核结果均尚未重新核实。未创建第二份申请、未取消个人申请、未接受新协议、未设置真实密钥或启用收款。

## 本轮开发

新增 `src/lib/server/alipay-web-pay.ts` 协议层，参考支付宝官方 Easy SDK 和网页支付异步通知说明：

- 手机网站 `alipay.trade.wap.pay` 与电脑网站 `alipay.trade.page.pay` 共用服务端订单号和整数分金额；返回签名后的 POST 字段，电脑端使用官方收银台，不将固定收款图当作订单二维码。
- RSA2 请求签名；支付宝公钥验签；通知中 AppID、seller_id、订单号、总金额二次核对。
- 仅交易成功或交易结束返回 paid=true；等待付款、关闭不计为支付成功；拒绝重复参数、超大报文和畸形字段。
- 沙箱和生产网关明确隔离，没有使用之前个人 AppID 或账号作为默认值。测试密钥每次在内存生成，不存储、不上传、不发起付款。

这只是协议层，不是完整上线接口：尚未增加支付 HTTP 入口或通知路由，没有落库，没有通知去重，没有把 paid=true 接到课程履约。现有手工收款界面仍是旧实现，不代表本轮已切换成功。

验证结果：`node --test scripts/commerce.test.cjs` 共 19 项通过（新增 4 项支付宝测试）；`tsc --project tsconfig.commerce.json` 通过。未进行生产构建、部署或真实支付测试。

## 接下来必须完成

1. 用户重新登录后核对法人授权、企业开户及认证主体，确认企业 AppID、seller_id、网站支付签约状态。
2. 新增支付意图和收款渠道迁移，订单/交易号唯一约束，以及同一订单重复通知、部分退款后通知的幂等处理。
3. 在受鉴权的下单接口中加载数据库价格和归属，禁止从客户端接受价格或回调地址；持久化支付请求后生成表单。
4. 通知路由先验签及对账，再原子写收款账本，提交后履约，失败可重试；return_url 只能展示查询状态，不能开通权益。
5. 主动查单、超时关单、退款、每日对账、过期/取消订单迟到付款处理，最后移除旧固定码正式入口并进行真实联调。
6. 真实企业密钥只进入服务端秘密配置。个人应用密钥不能替代企业应用；不提供凭据自动迁移或默认生产开关。
