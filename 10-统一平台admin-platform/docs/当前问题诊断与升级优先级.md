# 当前问题诊断与升级优先级

## 构建状态

当前新平台：

```text
npm run build 通过
```

说明工程基础可用。

但通过不代表平台已经设计正确。

## P0 问题

### 1. 新平台仍有旧系统拼装痕迹

原发现：

```text
src/app/(admin)/content/page.tsx
src/app/(admin)/training/page.tsx
src/app/(admin)/online-course/page.tsx
src/app/api/html-proxy/route.ts
src/app/api/html-proxy-netcourse/route.ts
```

问题：

```text
仍在通过 iframe 或 html-proxy 接旧页面。
```

处理方向：

```text
删除拼装思路
改成新平台原生页面
旧系统只提供数据
```

当前处理：

```text
已删除 src/app/api/html-proxy/route.ts
已删除 src/app/api/html-proxy-netcourse/route.ts
training 已改为统一平台原生开发页
online-course 已改为统一平台原生开发页
content 新建内容弹窗已改为原生表单
```

验证：

```text
src 内已无 iframe / html-proxy / dangerouslySetInnerHTML
```

### 2. API 调用分散

发现多个页面直接写：

```text
process.env.NEXT_PUBLIC_API_URL || 'http://localhost:3000/api'
```

问题：

```text
接口入口分散
后续换域名、换网关、加鉴权都容易漏
```

处理方向：

```text
统一进入 src/lib/api.ts
页面禁止直接拼 API_BASE
```

当前处理：

```text
新增 src/types/domain.ts
新增 src/lib/adapters/platform.ts
dashboard / members / orders / ecommerce / finance 已统一通过 platformAdapter 读取数据
courses / permissions / settings 已统一通过 platformAdapter 读取数据或平台配置
```

### 3. 领域模型不统一

当前页面直接消费旧系统返回结构。

问题：

```text
旧系统字段一变，新平台页面就跟着坏
```

处理方向：

```text
src/lib/adapters
src/types/domain.ts
```

所有旧数据先转成统一模型。

当前已建立统一模型：

```text
Member
UnifiedOrder
Product
EcommerceSummary
FinanceSummary
DashboardData
```

## 新开发节奏

不要再同时铺 20 个模块。

建议节奏：

```text
第 1 天：清除 iframe/html-proxy 依赖，建立 adapters 和 domain types
第 2 天：重做 dashboard / members / orders 三个核心页面
第 3 天：重做 ecommerce / finance 两个业务页面
第 4 天：统一权限、空状态、错误处理、加载态
第 5 天：联调旧系统真实数据，跑 build，准备部署
```

## 判断标准

这次升级是否成功，看四件事：

```text
新平台能独立打开
新平台能独立登录
新平台能读真实核心数据
新平台不再拼旧后台页面
```

达不到这四条，就不能说统一平台完成。
