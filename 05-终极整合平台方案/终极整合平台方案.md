### 目标架构

```
前端层: 官网(Next.js) → 学员H5(Vue3/React) → 小程序(原生)
                                 │
API网关层: Nginx反向代理 + API统一路由
                                 │
后端服务层: Express微服务架构
  ├── auth-service（认证）
  ├── member-service（学员）
  ├── course-service（课程）
  ├── order-service（订单+支付）
  ├── distribution-service（分销）
  └── material-service（素材）
                                 │
数据层: SQLite（开发）→ MySQL（生产）+ Redis（缓存）
                                 │
存储层: 本地（开发）→ 阿里云OSS（生产）
                                 │
AI层: 通义千问（文案）+ 智谱GLM（推荐）
```

### 数据库架构（目标20+张表）

**现有核心表（6张）：**
- `User` - 管理员/店长/教师（含JWT认证）
- `Member` - 学员信息（手机号唯一索引）
- `Course` - 课程（线下+线上）
- `Payment` - 缴费记录（线下）
- `ConsumeRecord` - 核销记录
- `OperationLog` - 操作日志（含undo能力）

**阶段一新增表：**

- `CourseAuthorization` - 网课授权（purchase/grant/admin）
- `Material` - 素材管理
- `MaterialFolder` - 素材文件夹

**阶段二新增表：**
- `DistributionRelation` - 分销关系
- `CommissionRecord` - 分佣记录
- `InviteRecord` - 邀请记录

**阶段三新增表：**

## 六、关键质量标准

### 已形成的技术模式

1. **日期处理："格式容忍+统一存储+规范显示"三层模型**
   - 输入：parseExcelDate() 支持14+种日期格式
   - 存储：normailzeDate() 统一为 YYYY-MM-DD
   - 显示：操作日志保持 toLocaleString('zh-CN')

2. **数据库迁移策略：PRAGMA table_info + ALTER TABLE**
   - 初始化时检查列存在性
   - 缺失则 ALTER TABLE ADD COLUMN
   - 确保新旧版本兼容

3. **手机号唯一校验模式**
   - 创建会员前查询手机号
   - 已存在则自动关联+更新姓名
   - 防止重复学员

4. **图片路径匹配算法：Stripped Prefix Matching**
   - 中文字符截断导致的文件名差异
   - 通过去掉非字母数字后比较前缀匹配

5. **轻升级原则**
   - 数据已存在就用，缺失就模拟
   - 不做大规模重构
   - 渐进式升级，保持API兼容
