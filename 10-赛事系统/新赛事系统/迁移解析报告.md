# 旧赛事系统解析与重塑方案

## 现有资产

- 后端资产：`software-*.jar`、`software_cloud.sql`、`software_config.sql`，整体来自若依/微服务体系，赛事业务集中在 `dfwq_*` 表。
- 小程序资产：`小程序mp-vote`，微信原生小程序，入口包含首页、赛事详情、报名、个人中心、评委绑定、评委评分、成绩查看、排行。
- 表格资产：`产赛用户.xlsx`、`评委数据.xlsx`，用于补齐用户和评委清单。

## 小程序接口语义

- 登录与用户：`login`、`getUserinfo`、`saveUserinfo`、`sendSms`、`bindVoter`、`bindShow`、`unbind`
- 赛事与报名：`getCompList`、`getComp`、`getSignupCompList`、`getSignupTypes`、`getSignup`、`submitSignup`、`paySignup`、`signupEdit`、`signupEditDetail`
- 评委与评分：`getVoteList`、`getShow`、`submitRating`
- 成绩与排行：`getVoteDetail`、`payScore`、`getRank`
- 系统内容：`getSettings`、`uploadAvatar`

## 新系统模块

- 运营总览：赛事、用户、选手、评委、评分记录的集中看板。
- 赛事管理：赛事档案、报名开关、组别数、选手数、评委数、评分记录数。
- 报名管理：选手、节目、组别、机构、指导老师、支付状态、历史分数。
- 评委管理：SQL 评委和 Excel 评委按手机号合并，显示参与赛事与评分数量。
- 评分核验：按赛事、组别、评分项聚合历史评分，提供平均分复核。
- 数据核验：旧数据来源、迁移数量、Excel/SQL 匹配关系、后台账号保留情况。
- 数据导出：可从页面导出完整 JSON 快照，便于后续接入数据库或接口。

## 后续工程路线

1. 数据库化：将 `legacy-data.js` 导入 SQLite/PostgreSQL，建立赛事、组别、报名、评委、评分外键关系。
2. 权限体系：保留旧 `sys_user` 作为主办方/管理员，普通用户与评委从 `dfwq_comps_user` 派生。
3. 小程序兼容接口：按旧接口名提供兼容层，让旧小程序可逐步迁移。
4. 新管理端接口：新增赛事 CRUD、组别编排、评委授权、成绩锁定、榜单发布。
5. 现场评分端：按赛事/组别/评委权限显示选手，支持分项评分、提交锁定、异常提示。
6. 成绩发布端：支持去最高最低分、权重项、并列排名、奖项名单导出。
