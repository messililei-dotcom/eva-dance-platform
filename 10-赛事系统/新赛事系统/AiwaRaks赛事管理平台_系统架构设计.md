# AiwaRaks赛事管理平台系统架构设计

> 系统定位：东方舞赛事全流程运营中枢  
> 核心方案：统一平台入口 + 赛事独立业务域 + 公共能力底座 + 数据融合架构  
> 适用范围：赛事报名、选手管理、评委评分、成绩发布、证书发放、财务统计、现场大屏、会员转化、数据复盘。

## 1. 产品定位

AiwaRaks赛事管理平台不是普通报名系统，而是：

- 赛事运营中枢
- 评分管理系统
- 学员数据沉淀系统
- 课程、会员、电商和训练营转化平台

最终目标是用赛事沉淀选手，用选手数据沉淀会员，用会员体系带动课程、电商、训练营和国际赛事品牌增长。

## 5. 核心业务流程

### 赛事创建

```text
创建赛事
→ 配置赛事基础信息
→ 上传海报和详情
→ 创建组别与场次
→ 设置报名费用
→ 设置评分规则
→ 设置评委授权
→ 发布赛事
```

### 选手报名

```text
用户进入小程序
→ 选择赛事
→ 选择组别
→ 填写选手信息
→ 填写节目/机构/老师
→ 上传音乐
→ 创建报名订单
→ 微信支付
→ 报名成功
→ 后台审核
```

### 评委评分

```text
评委登录
→ 绑定身份
→ 查看授权赛事
→ 进入授权组别
→ 查看当前选手
→ 按评分项打分
→ 提交评分
→ 系统保存原始分
→ 主控台查看评分进度
```

### 成绩发布

```text
评分完成
→ 系统检查漏评
→ 系统检测异常分
→ 成绩计算
→ 计分组复核
→ 锁定成绩
→ 发布排名
→ 生成获奖记录
→ 生成电子证书
→ 小程序开放查询
→ 大屏展示结果
```

## 6. 评分系统专项设计

评分系统是赛事平台的核心模块，必须独立设计。

### 评分规则能力

- 多评分项
- 不同组别使用不同评分模板
- 分项满分设置
- 权重设置
- 去最高分
- 去最低分
- 平均分
- 总分计算
- 排名规则
- 并列处理
- 小数位控制

### 评分安全机制

- 评委只能看授权组别
- 评委不能修改已锁定评分
- 每次评分保存操作日志
- 成绩发布前可复核
- 发布后修改必须留痕
- 原始评分记录不可物理删除
- 异常评分自动提醒

### 评分状态机

```text
未开始
→ 评分中
→ 评分完成
→ 待复核
→ 已锁定
→ 已发布
→ 已归档
```

## 8. API 设计

采用版本化 REST 风格：

```text
/api/v1/platform/...
/api/v1/event/...
/api/v1/judging/...
/api/v1/results/...
/api/v1/admin/...
```

核心接口分组：

- 赛事：`/api/v1/event/events`
- 报名：`/api/v1/event/registrations`
- 评分：`/api/v1/judging/...`
- 成绩：`/api/v1/results/...`
- 平台公共能力：`/api/v1/platform/...`

旧小程序通过兼容层逐步迁移：

```text
旧小程序接口
→ 兼容 API 层
→ 新业务服务
→ 新数据库
```

## 9. 技术选型

后端建议：

- Java Spring Boot / Spring Cloud，适合承接旧系统经验
- 或 Node.js NestJS，适合快速迭代
- MySQL 8
- Redis
- OSS/COS 对象存储
- JWT + RBAC 权限
- API Gateway

前端建议：

- 管理后台：Vue 3 + TypeScript + Element Plus，或 React + Ant Design Pro
- 小程序：微信原生小程序，或 uni-app / Taro
- 大屏端：Vue/React + WebSocket

部署建议：

- 初期采用模块化单体部署
- 后期按评分、成绩、大屏等压力点拆服务

## 11. 验收标准

### 数据验收

- 旧赛事数据完整导入
- 旧报名数据完整导入
- 旧评委数据完整导入
- 旧评分记录完整导入
- 每条迁移数据可追溯旧 ID
- 异常数据有清单

### 功能验收

- 可以创建一场新赛事
- 可以配置组别和评分规则
- 选手可以在线报名并支付
- 评委可以对授权组别评分
- 系统可以自动计算成绩
- 管理员可以复核并发布成绩
- 选手可以查询成绩和证书
- 大屏可以展示当前赛事状态

### 稳定性验收

- 评分提交无明显延迟
- 多评委同时评分不冲突
- 成绩计算结果可复核
- 断网/刷新后评分状态不丢失
- 重要操作均有日志

## 12. 最终建议

AiwaRaks赛事管理平台不要按照普通“报名系统”建设，而应作为伊娃东方舞长期的赛事数字化资产来建设。

系统必须同时满足三个目标：

1. 现场可用：比赛当天稳定、快速、可控。
2. 数据可用：历史数据、评分数据、报名数据可查询、可分析、可复盘。
3. 商业可用：赛事结束后还能继续转化课程、会员、电商和线下活动。
