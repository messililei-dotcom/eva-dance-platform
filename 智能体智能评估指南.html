🎯 你的 AI Agent 到底有多聪明？
—— 14 维度智能度评估框架完全指南

智能体研习社 · 圆规 · 2026-06-02

"你的 Agent 到底有多聪明？这个数字是涨了还是跌了？
—— 大多数改进停留在'感觉好了'，现在，让能力进化变得可测量。"

2026年，AI Agent 的数量正以指数级增长。从个人助手到企业自动化，从代码开发到金融投研，每个 Agent 都在宣称自己"更智能"。但一个核心问题始终悬而未决——我们到底如何衡量一个 Agent 的智能度？

直觉式的"感觉变好了"不再是答案。我们需要的是一个可量化、可重复、可追踪的评估体系。

来自开发者 圆规 的开源项目 smartness-eval，正是为此而生。它提供一个 14 维度 的 AI Agent 智能度评估框架，将真实运行数据转化为结构化、可重复的智能度评分，并支持置信区间、趋势追踪和反作弊探针——对齐 CLEAR、T-Eval、Anthropic 等国际评测标准。

项目地址：github.com/xyva-yuangui/smartness-eval ⭐

◆ ◆ ◆

一、评估框架核心

smartness-eval 将三种评估信号融合为一个综合评分：

📡 三大评估信号
🧪
任务测试
34 项自动化测试命令，覆盖 14 个维度
📊
运行时遥测
真实日志、延迟指标、错误追踪、推理知识库
🛡️
反作弊探针
评估时注入随机输入，防止过拟合已知测试
📋
报告输出
JSON + Markdown，含评分、置信区间、趋势对比

每一次评估产出的不是一个冰冷数字，而是一份完整的 智能度体检报告：总体评分、各维度细分、置信区间、风险标记、趋势变化、升级建议——一目了然。

◆ ◆ ◆

二、14 维度智能度评估体系

评估体系分为 7 大主维度 和 7 大扩展维度，覆盖 Agent 智能的核心能力边界。每个维度配备 0–5 级详细评分量表。

🏆 7 大主维度（权重 63%）

# 维度 权重 衡量内容
1 理解能力 🧠 9% 意图识别、约束捕获、上下文一致性
2 分析能力 🔍 9% 问题分解、依赖识别、结构化输出
3 思考能力 🤔 9% 风险意识、自我检查、对抗性推理
4 推理能力 🔗 13% 逻辑链完整性、证据支撑、置信校准
5 自我迭代 🔄 9% 错误修复率、模式升级、学习新鲜度
6 对话沟通 💬 9% 清晰度、完整性、可执行性、语气匹配
7 响应时长 ⚡ 5% P50/P95 延迟、超时率、API 链健康度

🚀 7 大扩展维度（权重 37%）

# 维度 权重 衡量内容
8 鲁棒性 🛡️ 7% 噪音/长上下文/边界条件下的稳定性
9 泛化能力 🌐 5% 跨领域路由准确率、意图多样化
10 ⭐ 规划能力 📐 5% 任务分解、步骤排序、依赖管理、工作流执行
11 ⭐ 幻觉控制 🎯 6% 事实准确性、接地响应、不确定时拒绝回答
12 策略遵循 📏 5% AGENTS.md 合规性、安全确认、操作约束
13 工具可靠性 🔧 4% 脚本可用性、Cron 健康度、状态文件完整性
14 校准能力 ⚖️ 5% 不确定性表达、置信准确度、高置信错误率

其中 ⭐ 标记的"规划能力"和"幻觉控制"为 v0.3.0 新增维度，对齐 CLEAR 框架、T-Eval（ACL 2024）及 Anthropic Agent 评估 标准。

◆ ◆ ◆

三、三种评估模式：按需选择深度

针对不同场景和需求，smartness-eval 提供三种评估模式：

⚡ Quick
~12 项测试 · 3 天数据窗口 · 1x 重复 · 1 个探针
每日自省
📊 Standard
~30 项测试 · 7 天数据窗口 · 1x 重复 · 2 个探针
每周能力周报
🔬 Deep
全部测试 · 30 天数据窗口 · 2x 重复 · 3 个探针
月度审计 / 升级后
◆ ◆ ◆

四、快速上手：5 分钟跑起来

安装使用非常简单，无需任何外部依赖（仅需 Python 3.9+）：

# 1. 克隆项目 git clone https://github.com/xyva-yuangui/smartness-eval.git cd smartness-eval # 2. 检查结构完整性 python3 scripts/check.py # 3. 快速评估（~10 项测试，3 天数据窗口） python3 scripts/eval.py --mode quick --no-probes # 4. 标准评估 + Markdown 报告 python3 scripts/eval.py --mode standard --format markdown # 5. 深度评估 + 趋势对比 python3 scripts/eval.py --mode deep --compare-last
🔧 CLI 参数一览
参数 说明
--mode评估深度：quick / standard / deep
--format输出格式：json / markdown
--compare-last与上次评估对比趋势
--llm-judge启用 LLM 主观评分（需 API Key）
--no-probes关闭反作弊探针

六、底层评分逻辑：数字如何炼成？

每个维度的最终得分 = 任务测试得分 × 权重 + 真实运行指标 × 权重。

以 reasoning（推理能力）维度为例——

# reasoning（推理）评分公式 reasoning = task_score × 0.40 + benchmark_pass_rate × 0.15 + reasoning_depth × 0.25 # 高置信条目占比 + reasoning_total × 0.20 # 知识库总量（上限 120 条）

评分公式的设计哲学：

📝
任务测试
标准化试题，衡量"能不能"
📈
运行指标
真实数据，衡量"做没做"
⚖️
加权融合
测试与实战各取所需，全面评估
🔬
趋势对比
--compare-last 追踪各维度变化

完整评分公式见项目 docs/SCORING.md。

八、安全第一：多层防护机制

由于执行自动化测试涉及 subprocess，smartness-eval 内置了严格的安全执行模型：

🔒 安全执行规则
🟢 解释器白名单
仅允许 python3
🔴 禁止内联执行
拦截 -c 和 exec(
🔴 禁止绝对路径
所有路径必须相对
🔴 禁止路径穿越
拒绝 .. 段
🟢 前缀白名单
仅限 scripts/, skills/…, state/, benchmarks/
🔴 默认网络关闭
--llm-judge 需显式启用 + API Key

九、评估输出：体检报告的格式

每次评估产生 3 份输出文件，满足不同场景需求：

文件 路径 用途
📄 Run JSON state/smartness-eval/runs/<timestamp>.json 完整结构化结果，适合程序分析
📝 Markdown 报告 state/smartness-eval/reports/<date>.md 人类可读报告，适合分享
📊 历史记录 state/smartness-eval/history.jsonl 每次评估一行，支持中长期趋势分析
